## 速查表

1. **有带走物的教程/清单文必须有表**，不要只用 bullet 冒充「表」。
2. Markdown 用管道表，列说人话。推荐列：`Skill | 干什么 | 怎么喊 | 交什么`（可按题改名，但门外汉一秒懂）。
3. **开头**：全文金句后尽快放**一整份**表（别藏到文末才给）。
4. **结尾**：再放**同一整份**，方便收藏带走。
5. 单元格短、具体；禁内部黑话（扳手、排产口令给 AI 看的写法等）。
6. 推箱后抽检：线上 HTML 是真 table，手机可左右滑；若变成「任务：…｜」竖排伪表 = 排版引擎坏了，先修 `md2huixin_gzh.py` 的 `table_html` 再推。

## 长图横拼

1. 同一步骤/同一案例有多张竖长静图 → **先横拼成 1 张**（或少张），再写进正文。
2. **禁止**正文连放「图1、图2、图3」逼读者一直往下划。
3. 动图/GIF 需要演示过程的可单独保留；静图优先拼。
4. 产物建议：`assets/.../stitched/`；正文只引用拼后文件。
